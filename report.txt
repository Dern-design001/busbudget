1. WHAT IS BUSBUDGET?
----------------------------------------------------------------
BusBudget is a personal daily budget tracking web application.
It lets you log your daily budget, track expenses across 4
categories (Food, Bus, Auto, Bike), and see how much you saved
each day. Data is stored permanently in a PostgreSQL database
and the app is secured with Google OAuth login.

Key features:
  - Google OAuth login (sign in with your Google account)
  - Per-user private data (each user sees only their entries)
  - Dashboard with total budget, spent, saved, net wallet stats
  - Add / Edit / Delete daily entries
  - Multiple expense items per day
  - Search and sort entries
  - Dark / Light mode toggle
  - Mobile-first responsive design
  - Live savings preview while filling the form
  - Data stored in PostgreSQL (cloud + local)
  - Deployed live at https://busbudget.onrender.com

2. TECH STACK
----------------------------------------------------------------
  Frontend   : HTML5, Tailwind CSS (CDN), Vanilla JavaScript
  Backend    : Node.js + Express.js (v5)
  Database   : PostgreSQL 18 (local) / Render PostgreSQL (cloud)
  Auth       : Google OAuth 2.0 via Passport.js
  Sessions   : express-session + connect-pg-simple (DB sessions)
  DB Driver  : pg (node-postgres)
  Other      : dotenv, cors

  Purpose : Express HTTP server — handles all requests.
  What it does:
    1. Loads .env
    2. Sets up middleware:
       - cors()            → allows browser API calls
       - express.json()    → parses JSON bodies
    3. Sets up session (stored in PostgreSQL via pgSession)
       - 7 day cookie lifetime
       - httpOnly + sameSite for security
    4. Initialises Passport (Google OAuth)
    5. Serves static files (index.html, css/, js/)
    6. Mounts routes:
       /auth         → auth/routes.js
       /api/entries  → routes/entries.js
    7. Fallback → serves index.html
    8. Listens on PORT (3000 local, auto on Render)

  GET /auth/google
    → Redirects browser to Google login page
    → Requests 'profile' and 'email' scopes

  GET /auth/google/callback
    → Google redirects here after login
    → On success: redirect to /
    → On failure: redirect to /?error=auth_failed

  GET /auth/logout
    → Clears session, destroys cookie
    → Redirects to / (shows login screen again)

  GET /auth/me
    → Returns current logged-in user as JSON
    → { id, name, email, avatar }
    → 401 if not authenticated
    → Called by frontend on every page load

6. HOW EVERYTHING CONNECTS (DATA FLOW)
----------------------------------------------------------------

  USER OPENS APP (https://busbudget.onrender.com)
      │
      ▼
  Browser loads index.html from Express static server
      │
      ▼
  window.onload → initAuth() → GET /auth/me
      │
      ├── 401 Not logged in → show "Continue with Google" screen
      │
      └── 200 Logged in → showApp() → loadEntries()
                               │
                         GET /api/entries
                               │
                         requireAuth middleware checks session
                               │
                         SELECT * FROM entries WHERE user_id=$1
                               │
                         Returns user's entries as JSON
                               │
                         renderDashboard() + renderEntryList()

  USER CLICKS "CONTINUE WITH GOOGLE"
      │
      ▼
  Browser → GET /auth/google
      │
      ▼
  Redirect to Google login page
      │
      ▼
  User logs in with Gmail
      │
      ▼
  Google → GET /auth/google/callback
      │
      ▼
  passport.js finds/creates user in DB
      │
      ▼
  Session created → stored in session table in PostgreSQL
      │
      ▼
  Redirect to / → initAuth() detects session → showApp()

  USER ADDS AN ENTRY
      │
      ▼
  POST /api/entries (with user_id from session)
      │
      ▼
  INSERT INTO entries ... WHERE user_id = req.user.id
      │
      ▼
  loadEntries() → UI refreshed

  USER SIGNS OUT
      │
      ▼
  GET /auth/logout → session destroyed
      │
      ▼
  Redirect to / → initAuth() → 401 → showLoginScreen()

7. DATABASE TABLES
----------------------------------------------------------------

  Table: users
  ─────────────────────────────────────────────────────────
  id          SERIAL       Auto-increment primary key
  google_id   TEXT         Unique Google account identifier
  email       TEXT         Gmail address
  name        TEXT         Display name from Google profile
  avatar      TEXT         Profile picture URL
  created_at  TIMESTAMPTZ  When user first logged in

  Table: entries
  ─────────────────────────────────────────────────────────
  id          TEXT         "id-<timestamp>" format
  date        DATE         YYYY-MM-DD, unique per user
  budget      NUMERIC      Daily budget (INR)
  spent       NUMERIC      Sum of expenses
  saved       NUMERIC      budget - spent
  expenses    JSONB        [{"name":"...","category":"...","amount":0}]
  user_id     INTEGER      FK → users.id (CASCADE DELETE)
  created_at  TIMESTAMPTZ  Auto timestamp

  Table: session
  ─────────────────────────────────────────────────────────
  sid         VARCHAR      Session ID (primary key)
  sess        JSON         Session payload
  expire      TIMESTAMP    Expiry time (7 days)

11. HOW TO RUN LOCALLY
----------------------------------------------------------------

  Prerequisites:
    - Node.js installed
    - PostgreSQL running locally
    - busbudget database created
    - Tables created (run schema.sql + schema_users.sql)
    - .env filled with local credentials + Google OAuth keys

  Steps:
    1. npm install
    2. npm start          (or npm run dev for auto-restart)
    3. Open http://localhost:3000

  Local Google OAuth callback URL:
    http://localhost:3000/auth/google/callback
    (must be in Google Console → Authorised redirect URIs)

----------------------------------------------------------------
12. HOW TO DEPLOY (RENDER)
----------------------------------------------------------------

  1. Push code to GitHub (git push)
  2. Render auto-detects the push and redeploys
  3. Environment variables stay set in Render dashboard
  4. Production DB is on Render PostgreSQL (separate service)

  Production Google OAuth callback URL:
    https://busbudget.onrender.com/auth/google/callback
    (must be in Google Console → Authorised redirect URIs)

----------------------------------------------------------------
13. SECURITY NOTES
----------------------------------------------------------------

  - .env is in .gitignore — credentials never on GitHub
  - All DB queries use parameterized values ($1, $2...)
    preventing SQL injection
  - Sessions stored in PostgreSQL (not memory) — survive restarts
  - Google OAuth — no passwords stored, Google handles auth
  - user_id scoping — users can only access their own data
  - httpOnly session cookie — not accessible by JavaScript
  - SSL enforced for Render DB connection
