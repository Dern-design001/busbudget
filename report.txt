1. WHAT IS BUSBUDGET?
----------------------------------------------------------------
BusBudget is a personal daily budget tracking web application.
It lets you log your daily budget, track expenses across 4
categories (Food, Bus, Auto, Bike), and see how much you saved
each day. Data is stored permanently in a PostgreSQL database.

Key features:
  - 4-digit PIN lock to protect your data
  - Dashboard with total budget, spent, saved, net wallet stats
  - Add / Edit / Delete daily entries
  - Multiple expense items per day
  - Search and sort entries
  - Dark / Light mode toggle
  - Mobile-first responsive design
  - Live savings preview while filling the form
  - Data stored in PostgreSQL (not just browser memory)

  Purpose : REST API — all database operations for entries.
  Base URL: /api/entries

  ROUTE 1 — GET /api/entries
    Action  : Fetch all entries from DB
    Query   : SELECT * FROM entries ORDER BY date DESC
    Returns : JSON array of all entry rows
    Used by : loadEntries() in js/app.js on page load

  ROUTE 2 — POST /api/entries
    Action  : Create a new entry
    Requires: id, date, budget in request body
    Query   : INSERT INTO entries ... VALUES (...)
    Returns : The newly created row (201 Created)
    Error   : 409 if an entry for that date already exists
    Used by : saveEntry() in js/entries.js

  ROUTE 3 — PUT /api/entries/:id
    Action  : Update an existing entry by id
    Query   : UPDATE entries SET ... WHERE id=$6
    Returns : The updated row
    Error   : 404 if entry not found
    Used by : saveEntry() in js/entries.js (when editing)

  ROUTE 4 — DELETE /api/entries/:id
    Action  : Delete an entry by id
    Query   : DELETE FROM entries WHERE id=$1
    Returns : { success: true }
    Error   : 404 if entry not found
    Used by : deleteEntry() in js/entries.js

                        When 4 digits entered → calls processPin().

5. HOW EVERYTHING CONNECTS (DATA FLOW)
----------------------------------------------------------------

  USER OPENS APP
      │
      ▼
  Browser loads index.html from Express static server
      │
      ▼
  JS files load in order: config → auth → ui → dashboard
                          → entries → app
      │
      ▼
  window.onload fires (app.js)
      ├── initTheme()    → applies dark/light
      ├── initAuth()     → shows PIN gate
      ├── setTodayDate() → sets form date
      └── loadEntries()  → GET /api/entries
                               │
                         Express server receives request
                               │
                         routes/entries.js queries PostgreSQL
                               │
                         SELECT * FROM entries ORDER BY date DESC
                               │
                         Returns JSON array to browser
                               │
                         appState.entries = normalized data
                               │
                         renderDashboard() + renderEntryList()

  USER ADDS AN ENTRY
      │
      ▼
  Clicks "Add Log" → openModal() → form shown
      │
      ▼
  Fills date, budget, adds expense rows
  calculateSavingsPreview() fires on every input
      │
      ▼
  Clicks "Save Entry" → saveEntry(e)
      │
      ▼
  POST /api/entries  →  routes/entries.js
      │
      ▼
  INSERT INTO entries ... VALUES (...)
      │
      ▼
  DB confirms → loadEntries() called → UI refreshed

  USER EDITS AN ENTRY
      │
      ▼
  Clicks edit icon → editEntry(id)
      │
      ▼
  Modal opens pre-filled → saveEntry()
      │
      ▼
  PUT /api/entries/:id → UPDATE entries SET ... WHERE id=...
      │
      ▼
  DB confirms → loadEntries() → UI refreshed

  USER DELETES AN ENTRY
      │
      ▼
  Clicks trash icon → deleteEntry(id)
      │
      ▼
  Confirm dialog shown
      │
      ▼
  Clicks "Delete" → DELETE /api/entries/:id
      │
      ▼
  DB row removed → loadEntries() → UI refreshed

6. DATABASE TABLE DETAILS
----------------------------------------------------------------

  Table name : entries
  Database   : busbudget
  PostgreSQL : version 18

  Column       Type         Notes
  -----------  -----------  ----------------------------------
  id           TEXT         Primary key. Format: "id-<timestamp>"
  date         DATE         Unique per day. Format: YYYY-MM-DD
  budget       NUMERIC      Daily budget in INR (rupees)
  spent        NUMERIC      Sum of all expense amounts
  saved        NUMERIC      budget - spent (can be negative)
  expenses     JSONB        Array of expense objects:
                            [
                              {
                                "name": "Bus to office",
                                "category": "Bus",
                                "amount": 50
                              },
                              ...
                            ]
  created_at   TIMESTAMPTZ  Auto timestamp when row created

  Index: idx_entries_date ON entries(date DESC)
  Reason: Speeds up ORDER BY date DESC queries significantly.

  busbudget_pin       Stores base64-encoded PIN for app lock
  busbudget_session   'ok' while user is logged in this tab
  busbudget_prefs     Stores { theme, activeTab } preferences

  NOTE: Entry data is NO LONGER stored in localStorage.
        It is stored in PostgreSQL only.

8. API ENDPOINTS SUMMARY
----------------------------------------------------------------

  Method   URL                    Action
  -------  ---------------------  ----------------------------
  GET      /api/entries           Get all entries (newest first)
  POST     /api/entries           Create new entry
  PUT      /api/entries/:id       Update entry by id
  DELETE   /api/entries/:id       Delete entry by id

  All endpoints:
    - Accept/return JSON
    - Return appropriate HTTP status codes
      (200, 201, 400, 404, 409, 500)
    - Use parameterized queries (safe from SQL injection)

10. HOW TO RUN THE PROJECT
----------------------------------------------------------------

  Prerequisites:
    - Node.js installed (v18+)
    - PostgreSQL installed and running
    - busbudget database created
    - entries table created (run schema.sql)

  Steps:
    1. Fill in DB credentials in .env
    2. Open terminal in project folder
    3. Run: npm install      (first time only)
    4. Run: npm start
    5. Open: http://localhost:3000

  Dev mode (auto-restart on file save):
    npm run dev

----------------------------------------------------------------
11. SECURITY NOTES
----------------------------------------------------------------

  - .env is in .gitignore — credentials never go to GitHub
  - All DB queries use parameterized values ($1, $2...) 
    preventing SQL injection
  - PIN is stored as base64 (obfuscated, not plain text)
    Note: base64 is NOT encryption — for stronger security,
    consider bcrypt hashing for the PIN in the future
  - CORS is enabled broadly — for production, restrict to
    your actual domain
